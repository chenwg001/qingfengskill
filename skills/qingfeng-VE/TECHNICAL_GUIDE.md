## 一、设计初衷与背景

### 1.1 为什么做这个技能？

制作此技能（工作流）的灵感来源于一次视频剪辑经历。前段时间单位组织一次趣味活动，要求我全程摄像并能在下午活动结束时把视频剪辑出来。虽说这对自己来说也是第一次，但谁让我是"高手"呢。要在短时间内完成素材的选取编辑，并生成一个相对完整的活动剪影视频，我第一时间想到了一个开源工具"短视频工厂"。 当天，我用"短视频工厂"在视频剪辑过程中，遇到了三个核心痛点：

**痛点一：素材使用不可控**

* 传统混剪工具虽然功能强大，但素材出场顺序完全依赖手动调整

* 批量处理时，AI 工具往往随机抽取片段，无法保证"每个素材必出现、按指定顺序出场"

* 需要逐条检查每条素材是否都在视频中，反复调试耗时耗力

**痛点二：音画同步不精准**

* 配音生成后，画面时长需要根据配音时长反推，传统工具需要手动调整转场

* 字幕时间轴需要手动对齐每一句配音，效率极低

* 多段剪辑拼接时，各段配音和字幕容易错位

**痛点三：流程不可复现**

* 每次剪辑都是独立操作，无法记录配置参数

* 同样的素材和文案，重做时需要重新调整所有设置

* 缺乏标准化的输出格式，难以批量生产

**本技能的解决方案：**

* **确定性剪辑**：所有参数可配置、可记录、可复现

* **智能时长匹配**：自动根据配音时长反推每段素材时长

* **句级字幕同步**：自动对齐每句配音的时间轴

* **一次性配置**：填写配置模板后，AI 自动执行全流程

### 1.2 使用场景

**核心场景：快速剪辑（现拍现剪现用）**

这个技能特别适合以下场景：

* **活动现场快速剪辑**：活动结束前完成素材收集，活动开始前生成视频

* **教育记录视频**：活动照片、现场录像快速生成纪念视频

* **会议报道剪辑**：会议纪要、活动报道视频快速制作

* **短视频批量生产**：多期内容快速剪辑，保持风格统一

**典型工作流：**

1. 拍摄/收集素材（按序号命名，如 1.mp4, 2.mp4）

2. 准备配音文案（可直接使用、或让 AI 生成）

3. 填写配置模板（5-10分钟）

4. AI 自动执行全流程（5-15分钟）

5. 交付成片![](TECHNICAL_GUIDE_md_files/b76449b0-9c91-11f1-99dc-3789589b9787.jpeg?v=1&type=image)

### 1.3 突出优点

#### （1）素材控制能力

* **出场顺序可控**：素材按文件编号排序，小号先出现

* **每条素材必出现**：通过时长规划确保所有素材被使用

* **时长精准匹配**：每段素材时长 = 配音时长 / 素材数量

#### （2）音画同步能力

* **句级字幕对齐**：每句话的字幕时间戳精确匹配配音

* **配音时长反推**：视频总时长 = 配音时长 + 缓冲时间（默认3秒）

* **句级时间轴**：本地 TTS 克隆时，逐句生成配音，获取真实时长

#### （3）分段剪辑设计

* **A模式**：一剪到底，适合单段视频

* **B模式**：分段剪辑，每段独立配音、独立字幕、独立混剪

* **段间硬切**：各段纯拼接，不重新混音，保持段内音画同步

#### （4）一次性配置

* 完整配置模板（10项参数）

* 必填项标识清晰

* AI 自动执行全流程，无需人工干预![](TECHNICAL_GUIDE_md_files/be7a8ed0-9c91-11f1-99dc-3789589b9787.jpeg?v=1&type=image)

## 三、核心算法详解

### 3.1 配音生成算法

#### edge-tts 模式（默认）

文本 -> 分句 -> 分组（每4句）-> 单次请求 -> 获取时长 -> 按比例分配

**关键设计：**

* 每次连接 4 句，避免被微软 TTS 接口限流

* 段时长按句内字数比例分配，实现句级近似对齐

* 缓存键包含 backend+voice 参数，防止缓存串用

#### 本地 TTS 克隆模式（可选）

文本 -> 逐句生成 -> 获取真实时长 -> 精确时间轴

**关键设计：**

* 逐句生成，获取每句真实时长

* 字幕时间轴精确匹配，无需近似分配

* 需配置 QWEN_TTS_MODEL_DIR 和 QWEN_TTS_PYTHON 环境变量

### 3.2 时长反推算法

**核心公式：**

```
V = T + args.video_extra  # 视频总时长
ideal = V / num_clips     # 每段理想时长
```

**场景处理：**

| 情况          | 处理方式                   |
| ----------- | ---------------------- |
| ideal >= 5秒 | 每段理想时长，全部素材用上          |
| ideal < 5秒  | 前 m 段各 5 秒，末段补到 T，其余丢弃 |

**代码实现：**

```python
def plan_clips(T, num, min_clip=5.0):
    ideal = T / num
    if ideal >= min_clip:
        clips = [ideal] * num
    else:
        m = max(1, int((T - min_clip) // min_clip))
        last = T - m * min_clip
        clips = [min_clip] * m + [last]
    return clips
```

### 3.3 转场算法

**内置转场效果（13种）：**

* fade - 淡入淡出

* slideleft, slideright, slideup, slidedown - 滑动

* circlecrop, rectcrop - 圆形/矩形裁切

* distance - 距离缩放

* wipeleft, wiperight - 擦拭

* circleopen - 圆形展开

* smoothleft - 平滑左移

* mix - 自动循环使用以上所有效果

**交替策略：** 13种转场效果循环使用，避免单调

### 3.4 字幕同步算法

**句级时间轴构建：**

* 本地 TTS 模式：逐句精确时长

* edge-tts 模式：按字数比例分配

**ASS 字幕格式：**

```
[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:00:01.00,0:00:04.50,Default,,0,0,0,,第一句字幕内容
```

### 3.5 混剪模式详解

#### A 模式（一剪到底）

* 所有素材放在同一目录

* 一次调用 mix_segment()

* 适合单段视频

#### B 模式（分段剪辑）

* 按 【1】【2】【3】 标记分段

* 每段独立配音、独立字幕、独立混剪

* 最终纯拼接（硬切，不重混音）

**为什么 B 模式段间硬切：**

* 各段内部音画已精确同步

* 交叉溶解会破坏段内同步

* 硬切保持每段的完整性

## 四、核心文件系列

### 4.1 主脚本：make_video.py

**功能：** 视频剪辑核心逻辑，支持 A/B 两种混剪模式

**核心函数：**

| 函数名                    | 功能        | 关键参数                          |
| ---------------------- | --------- | ----------------------------- |
| make_voiceover()       | 生成配音      | backend, voice, ref, language |
| plan_clips()           | 反推每段时长    | T（配音时长）, num（素材数）             |
| build_clip_plan()      | 规划素材时长分配  | durations, plan_target        |
| concat_xfade()         | 转场拼接素材    | scenes, transitions           |
| burn_and_mux()         | 烧录字幕+混流音频 | video, ass, audio             |
| join_segments_intact() | 纯拼接片段     | parts（列表）                     |
| generate_intro_video() | 生成片头视频    | title, image_path, duration   |
| generate_outro_video() | 生成片尾视频    | lines, duration               |

**CLI 参数示例：**

```bash
python make_video.py \
  --script work/script.txt \
  --materials "素材目录" \
  --output work/main.mp4 \
  --mode auto \
  --voice zh-CN-YunxiNeural \
  --ratio 16:9 \
  --backend edge \
  --bgm path/to/bgmi.mp3 \
  --bgm-gain 0.3
```

### 4.2 TTS 配音脚本：tts.py

**功能：** 双引擎 TTS 配音，支持在线和离线两种模式

**核心函数：**

* generate_edge() - edge-tts 在线配音

* generate_local() - 本地 Qwen3-TTS 克隆配音

**环境变量配置：**

* QWEN_TTS_MODEL_DIR：本地模型目录路径

* QWEN_TTS_PYTHON：带 qwen_tts 环境的 Python 解释器路径

* QWEN_TTS_REF：默认参考音频路径

### 4.3 BGM 生成脚本：gen_bgm.py

**功能：** 文本驱动的完整歌曲配乐生成（无需联网）

**段落结构：**

| 段落     | 配器                          | 密度  | 作用   |
| ------ | --------------------------- | --- | ---- |
| intro  | bass + pad                  | 0.8 | 引入情绪 |
| verse  | drums + bass + pad          | 1.8 | 主歌铺垫 |
| chorus | drums + bass + pad + melody | 2.6 | 高潮段落 |
| bridge | bass + pad                  | 1.2 | 过渡变化 |
| outro  | bass + pad                  | 0.6 | 收尾   |

**情绪映射：**

* 轻柔/舒缓 -> 低能量（0.30-0.32）

* 温暖/温情 -> 中能量（0.42-0.48）

* 轻快/欢喜 -> 高能量（0.70-0.85）

* 昂扬 -> 高能量（0.80）

### 4.4 视频工厂脚本：video_factory.py

**功能：** 辅助工具，用于快速测试和调试

**包含功能：**

1. 命令行参数 `--ref`

2. 环境变量 `QWEN_TTS_REF`

3. config.json 中的配置

4. 环境变量 `QWEN_TTS_MODEL_DIR` / `QWEN_TTS_PYTHON`

**TTS 引擎选择优先级：**

1. 命令行参数 `--backend`

2. 环境变量 `QWEN_TTS_PYTHON` 是否设置

3. 默认 edge（在线）

## 六、其他重要内容

### 6.1 常见错误与解决方案

#### 错误 1：FFmpeg 未找到

**现象：** ffprobe: command not found
**原因：** FFmpeg 未安装或未添加到 PATH
**解决：**

* Windows：从 https://ffmpeg.org/download.html 下载并添加到 PATH

* macOS：brew install ffmpeg

* Linux：sudo apt install ffmpeg

#### 错误 2：edge-tts 导入失败

**现象：** ModuleNotFoundError: No module named edge_tts
**原因：** 未安装 edge-tts
**解决：** pip install edge-tts

#### 错误 3：本地 TTS 环境未配置

**现象：** [错误] 未配置本地 TTS 环境，请设置环境变量 QWEN_TTS_PYTHON
**原因：** 使用了 --backend local 但未配置环境
**解决：** 设置环境变量 QWEN_TTS_PYTHON 和 QWEN_TTS_MODEL_DIR

#### 错误 4：素材目录为空

**现象：** 素材库为空
**原因：** 素材路径错误，或素材不在目录下
**解决：** 检查素材路径是否正确，确认素材文件存在

#### 错误 5：配音时长与视频时长不匹配

**现象：** 视频比配音长很多
**原因：** 旧版本代码强制 30 秒下限
**解决：** 已修复，现在 V = T + video_extra，不再强制下限

### 6.2 性能优化建议

#### 素材预处理

* 建议将素材统一转换为 mp4 格式（H.264 编码）

* 避免使用 mkv、webm 等格式，减少转码开销

* 素材分辨率建议 1080p 或 720p，过大分辨率会增加处理时间

#### 配音优化

* edge-tts 模式：每次请求最多 4 句，避免被限流

* 本地 TTS 模式：逐句生成，较慢但精确

* 配音缓存键包含文本内容，相同文本不重复生成

#### 存储优化

* 工作目录 work/ 存放临时文件，可定期清理

* 输出目录 output/ 存放最终成片

* 清理时保留：脚本、配置、素材、输出

### 6.3 扩展开发指南

#### 添加新转场效果

在 make_video.py 的 concat_xfade 函数中添加新转场名称即可。

#### 添加新音色

在 tts.py 的 generate_edge 函数中添加新音色名称，或让用户通过 --voice 参数指定。

#### 自定义 BGM 情绪映射

编辑 gen_bgm.py 中的 MOOD_ENERGY 字典，调整各情绪的能量值。

### 6.5 最佳实践建议

#### 素材准备

1. **命名规范**：按出场顺序编号（1.mp4, 2.mp4, ...）

2. **格式统一**：转换为 mp4（H.264 + AAC）

3. **时长建议**：单段素材 5-15 秒为宜

4. **分辨率统一**：同批素材尽量保持相同分辨率

#### 文案准备

1. **口语化**：避免书面语，读起来顺口

2. **断句清晰**：每句 15-30 字，便于字幕显示

3. **分段标记**：B 模式使用 【1】【2】... 标记

4. **时长预估**：4 字/秒 ≈ 40 字/10 秒

#### 配置填写

1. **必填项完整**：项目名称、文本来源、素材路径

2. **路径正确**：使用绝对路径或相对路径

3. **参数合理**：时长、音量等参数根据实际需要调整

4. **一次性配置**：尽量使用一键配置模板，减少人工干预

### 6.6 设计原则总结

1. **确定性**：所有参数可配置、可记录、可复现

2. **可控性**：素材出场顺序、时长分配、字幕同步均可精确控制

3. **快速性**：一次性配置后自动执行全流程，减少人工干预

4. **灵活性**：支持多种配置方式，适应不同场景需求

5. **扩展性**：模块化设计，易于添加新功能
